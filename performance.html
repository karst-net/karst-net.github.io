performance, measured

Comparing Karst's speed to WireGuard's isn't quite fair to WireGuard.

Every row below except Karst's does the same job with classical, pre-quantum cryptography — Curve25519 key exchange, the thing every mesh VPN built on WireGuard shares. Karst does a full post-quantum key establishment (ML-KEM-1024) and a post-quantum signature (ML-DSA-65) — algorithms NIST standardized for exactly this — on every connection, alongside established cryptography. That's real per-packet work the others simply don't do. We measured it anyway, on the same lab link, with the same instrument, back to back.

Single TCP + single UDP stream, 500 Mbps offered, turing ↔ lovelace over a 3×1G bonded LAN link. Full methodology and raw data linked below.

PQ marks the one row here doing post-quantum key establishment and signatures on every connection. WireGuard is the floor: a bare point-to-point kernel tunnel with no control plane at all, included as the reference every control-plane-mediated tool (Karst included) pays some cost against. Read this as "Karst is competitive with tools doing strictly less cryptographic work," not as a ranking — on a quiet, uncontended LAN, all five land within a fairly narrow band.

!
One lab LAN, one sitting, beta software throughout.

This is a single real-hardware run between two lab machines on one link — not a multi-site, multi-condition study, and Karst itself is beta with no external cryptographic review yet (see the security whitepaper). Multi-stream scaling, NAT/relay-forced paths, and reconvergence timing weren't measured here and are called out as open follow-ups in the full write-up.

the big idea

Built for tomorrow's maths, without giving up today's speed.

Harvest-now-decrypt-later means traffic encrypted with only classical cryptography today can be recorded and read once a sufficiently capable quantum computer exists. Karst's PHREATIC handshake closes that gap using NIST-standardized algorithms on every session — and still keeps pace with tools that don't.
